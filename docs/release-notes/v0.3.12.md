# Kestrel v0.3.12

**Status: personal beta.** Kestrel is not distributed outside direct AirDrop/USB handoff between Macs controlled by the developer; there is no App Store listing and no external user base. This note documents what changed for that audience.

## First tagged, provenance-verified release

This is the first git tag and GitHub Release this repository has ever cut. There is no prior tagged version to diff against, so this note does not claim a changelog against "v0.3.11" — that version was built and published from an uncommitted, untagged working tree and has no corresponding commit or tag in this repository's history. `v0.3.12` does not retroactively repair that artifact's provenance; it is the first release where source commit, tag, built app, GitHub Release, published artifact, and update manifest are all verifiably the same thing.

## Release-provenance safeguards (new in this cutover)

- `scripts/check-version.sh` enforces that `VERSION`, `apps/macos/project.yml`'s `MARKETING_VERSION`, `core/Cargo.toml`'s version, and every build config in `apps/macos/Kestrel.xcodeproj/project.pbxproj` agree — used both as a release preflight and in CI on every push/PR.
- `apps/macos/scripts/release-publish.sh` refuses to build or publish anything unless the working tree is clean, `HEAD` is tagged `vX.Y.Z` (an annotated tag), that tag is already pushed to `origin` at the exact commit being published, and every version source agrees with the tag — before any build step runs.
- The published `version.json` manifest now carries `sha256`, `commit`, `tag`, `published_at`, and `release_notes_url` alongside `version`/`url` (previously just the latter two).
- `apps/macos/Kestrel/Support/UpdateChecker.swift` verifies a downloaded update's SHA-256 against the manifest before unzipping it — a mismatch deletes the download and the update is never staged. Signed/notarized Developer ID + Team ID verification (already present) still runs before an update is staged for restart. Manifests without a `sha256` field (the legacy 2-field shape) skip the hash check by design, for backward compatibility.
- `.github/workflows/release-integrity.yml` runs the version-agreement check and the update-manifest/hash-verification test suite on every push and PR, with no signing credentials required.

## Memory / reindex queue recovery

The `core/memory` reindex-sweep job queue (pending/running/done/revival/missing-model states) has hardened test coverage: 247 deterministic tests plus a separately gated 8-test real-embedding-model integration suite (`cargo test -p memory -- --ignored`, run in CI only on `push` to `main`, where the pinned embedding model is downloaded first). No known regressions; this is coverage hardening for logic that already shipped, not a behavior change end users will notice directly.

## Other changes in this cutover

- Rust workspace formatting normalized (`cargo fmt --all`) across the whole `core/` tree — no semantic change.

## Known limitations

- Windows: `sync-engine`'s test binary cannot link (`rusqlite`'s bundled SQLite and `libsql`'s bundled SQLite define duplicate C symbols under MSVC's linker) — Windows CI builds `sync-engine` but does not run its tests. All other Windows-buildable crates are tested.
- Android: cross-compiled build/check only, no test execution (no Android test host in CI); `diarize`/`ffi` are excluded (no prebuilt ONNX Runtime for that target).
- The Google Calendar connector's dependency tree currently carries 3 pre-existing npm advisories (`hono`, `nanoid` — moderate/high, upstream), unrelated to this release and not yet remediated.
